You do not know your agent's
success rate. You know counts.

An agent workflow is an absorbing Markov chain: every step advances, retries, loops back, escalates or fails. Preflight solves that chain exactly — then propagates the uncertainty in the counts through the solve, so the answer arrives as an interval with a verdict attached.

Typed probabilities are a belief. Traces give counts. Counts in, credible intervals out — and when the data cannot settle your claim, the tool says so and tells you which step to go and observe.

Counts observed per step, straight from traces. Each step's transition vector is a Dirichlet posterior; edit a count and everything downstream recomputes. The back to column is the step index a loop-back returns to.

Assumption ledger

Every quantitative claim rests on assumptions. These are checked against the data rather than asserted, and each one records what it breaks if it fails.

05

Run it yourself

Numpy only. 45 tests, including the ones that check the solver against closed forms.

# counts straight from traces; the maths is deterministic
ev = [Evidence("Plan",     n_ok=1920, n_retry=40, n_fail=40),
      Evidence("Retrieve", n_ok=1980, n_retry=20),
      Evidence("Call tool",n_ok=1900, n_retry=60, n_fail=40),
      Evidence("Verify",   n_ok=34, n_back=4, n_esc=1, n_fail=1, back_to=2),
      Evidence("Answer",   n_ok=1960, n_retry=20, n_fail=20)]

p = propagate(ev)                 # posterior draws -> exact solve, batched
p["p_success"]                     # point 0.846, 90% CI [0.761, 0.908]
verdict(p, claim=0.85)            # -> underdetermined, 14.7 pts wide
value_of_info(ev, more=200)        # -> Verify: 14.8 -> 6.7 pts. Others: zero.

Five MCP tools: analyze, what_would_settle_it, check_littles_law, queue_latency, verifier_lift. The model supplies counts; the arithmetic is never left to the model.
